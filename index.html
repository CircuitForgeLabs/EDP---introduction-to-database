A Databases

A.1 What Is a Database?

At its core, a database is an organized collection of structured information, or data, typically stored electronically in a computer system. Think of it as a highly sophisticated, digital filing cabinet.

However, it is more than just a place to dump files. A database is managed by a Database Management System (DBMS). The DBMS is the software that interacts with end users, applications, and the database itself to capture and analyze the data. When we talk about "using SQL," we are typically interacting with a DBMS.

Key Characteristics of a Database

  • Organized — Data is stored in a structured way, making it easy to find, manage, and update.
  • Persistent — Data survives after the program that created it has been closed.
  • Shared — Multiple users or applications can access the data simultaneously (with proper controls).
  • Secure — Access to data can be controlled and restricted.

Why Are Databases Important?

  • Data Integrity — They enforce rules to ensure data is accurate and consistent.
  • Reduced Redundancy — They minimize duplicate data.
  • Scalability — They can grow to store vast amounts of data.
  • Concurrency — They manage access for many users at once without conflicts.
  • Security — They provide mechanisms to protect sensitive information.

A.2 Types of Databases

While there are many types, the most common for SQL users are Relational Databases (RDBMS).

🔗 Relational Database (RDBMS)

The classic type of database that SQL was designed for. It stores data in tables with rows and columns, and it defines relationships between these tables. Examples: MySQL, PostgreSQL, Microsoft SQL Server, Oracle Database, SQLite.

🧩 NoSQL Database

Non-relational databases designed for specific data models (like documents or key-value pairs), often used for large-scale, distributed systems. Examples: MongoDB (document), Redis (key-value), Neo4j (graph).

In this module, our focus is on Relational Databases and how we interact with them using SQL.

B Database Objects

A database is not just one big table. It is a container for several different types of objects that help organize and manage data. Here are the most important ones you will encounter when using SQL.

B.1 Tables

The Table is the most fundamental database object. It is where the actual data is stored. A table is a two-dimensional structure consisting of rows and columns.

  • Columns — also known as fields or attributes. Each column represents a specific piece of information (e.g. CustomerID, FirstName, Email). Every column has a specific data type (e.g. integer, text, date).
  • Rows — also known as records or tuples. Each row represents a single, unique instance of the data (e.g. a single customer).
Example: the Customers table
CustomerID (INT) FirstName (VARCHAR) LastName (VARCHAR) Email (VARCHAR)
1JohnDoejohn.doe@email.com
2JaneSmithjane.smith@email.com
3PeterJonespeter.jones@email.com

B.2 Views

A View is a virtual table based on the result set of an SQL statement. It is not a physical table and does not store data itself (with some exceptions, like materialized views). Instead, it is a saved query that acts like a table.

Purpose

  • Simplicity — To hide complex queries and present a simple, easy-to-use table to users.
  • Security — To restrict access to specific rows or columns of an underlying table. For example, a view could show only non-sensitive employee data.
  • Consistency — To provide a stable interface even if the underlying table structure changes.
SQL
CREATE VIEW ActiveCustomers AS
SELECT CustomerID, FirstName, LastName
FROM Customers
WHERE IsActive = 1;

Now, you can query ActiveCustomers just like a regular table.

B.3 Indexes

An Index is a special lookup table that the database search engine can use to speed up data retrieval. Think of it as the index at the back of a textbook.

  • Purpose — To significantly improve the performance of SELECT queries, particularly on large tables with WHERE clauses.
  • How it works — Without an index, the database must scan every row in a table to find the ones you want (a "full table scan"). With an index, it can find the data much faster.
  • Trade-off — While indexes speed up reads (queries), they can slow down writes (INSERT, UPDATE, DELETE) because the index itself must be updated.
SQL
CREATE INDEX idx_lastname
ON Customers (LastName);

This creates an index on the LastName column, making it much faster to find customers by their last name.

B.4 Stored Procedures and Functions

A Stored Procedure is prepared SQL code that you can save and reuse. It is like a script or a function in a programming language.

  • Purpose — To encapsulate business logic, perform complex operations, and improve performance by reducing network traffic.
  • How it works — You call the procedure by name, and it executes the SQL statements inside it, optionally using parameters you provide.
SQL
CREATE PROCEDURE GetCustomerByID (IN cust_id INT)
BEGIN
    SELECT * FROM Customers WHERE CustomerID = cust_id;
END;

You would then execute it with CALL GetCustomerByID(1);

B.5 Triggers

A Trigger is a special type of stored procedure that automatically executes in response to certain events on a particular table or view.

  • Purpose — To enforce business rules and maintain data integrity automatically.
  • Events — Triggers are usually fired by INSERT, UPDATE, or DELETE operations.
  • Example — You could create a trigger that automatically logs every time a customer's email is updated in an AuditLog table.

Quick recap: Tables store data, Views present it, Indexes speed it up, Procedures automate it, and Triggers react to it.

C Opening and Closing a Database

Unlike opening a text file on your computer, connecting to a database is a more formal process. In the world of SQL, "opening" a database is called connecting, and "closing" it is called disconnecting. This process is managed by the DBMS to ensure security and stability.

C.1 Opening (Connecting to) a Database

To work with a database, a client (like a command-line tool, a GUI application such as DBeaver or pgAdmin, or a program you have written) must establish a connection to the database server. This involves a few key pieces of information:

  • Host / Server — the address of the computer where the database server is running (e.g. localhost or an IP address).
  • Port — the specific port number the database server is listening on (e.g. 3306 for MySQL, 5432 for PostgreSQL).
  • Database Name — the specific database you want to work with.
  • Username & Password — credentials to authenticate and authorize your access.

How It Works

  1. Client request — Your SQL client sends a connection request to the database server with the credentials.
  2. Server verification — The DBMS verifies the credentials and checks whether you have permission to connect.
  3. Session established — If successful, a session is created, and you can now send SQL queries to the server.

In SQL

The USE command is used to "open" a specific database within an already established connection.

SQL
-- First, you connect using your client tool (this part is not a SQL command)
-- e.g. in a command line: mysql -h localhost -u myuser -p

-- Now you are connected to the server. To start working with a specific database:
USE MyDatabase;

-- From now on, all queries will be run against the MyDatabase database.

C.2 Closing (Disconnecting from) a Database

It is crucial to properly close your connection when you are finished. Failing to do so consumes server resources and can lead to problems.

Purpose

  • Frees up resources — the server can reclaim the memory and processing power used by your session.
  • Releases locks — if your session held any locks on tables or rows, disconnecting releases them, allowing other users to work.
  • Security — it ends your authenticated session, preventing unauthorized use.

How It Works

The client sends a disconnect command to the server. The server then terminates the session and cleans up any associated resources.

In SQL

MySQL command-line client:

SQL
EXIT;
-- or
QUIT;

PostgreSQL client (psql):

psql
\q

In a programming language (e.g. Python):

Python
# After you are done with your cursor and queries
connection.close()

Best practice: Always close your connection when you are finished. In GUI tools, click "Disconnect". In scripts, call close() — ideally inside a finally block or a context manager so it always runs.

✓ Summary & Key Takeaways

Remember these points

  • A Database is an organized collection of data managed by a DBMS.
  • Relational Databases store data in tables and are the primary use case for SQL.
  • Key Database Objects:
    • Tables — store the actual data in rows and columns.
    • Views — virtual tables based on a saved query, used for simplicity and security.
    • Indexes — speed up data retrieval.
    • Stored Procedures — reusable blocks of SQL code.
    • Triggers — automatically run code in response to data changes.
  • Opening a database means establishing a connection to the database server using credentials.
  • Closing a database means disconnecting from the server to free up resources and maintain security.

🛠 Hands-On Exercise

  1. Install a DBMS. Download and install a free, open-source database such as PostgreSQL or MySQL. Also install a GUI client like DBeaver or pgAdmin to make it easier to interact with the database.
  2. Connect. Use your client to connect to your local database server using the credentials you set up during installation.
  3. Create a database. Write a CREATE DATABASE statement to create a new database called LearningDB.
  4. Use the database. Run USE LearningDB; (or your client's equivalent) to "open" it.
  5. Create a table. Write a CREATE TABLE statement to create a simple Students table with columns such as StudentID, FirstName, and LastName.
  6. Create an index. Create an index on the LastName column.
  7. Disconnect. Use your client's "Disconnect" button or the appropriate command to properly close your connection.
  8. Reconnect. Connect again and run SELECT * FROM Students; to prove you are in the correct database.

📖 Glossary of Terms

DBMSDatabase Management System — software that manages databases.
RDBMSRelational Database Management System — a type of DBMS that stores data in related tables.
SQLStructured Query Language — the standard language for interacting with relational databases.
TableA database object that stores data in rows and columns.
Row / RecordA single entry in a table.
Column / FieldA specific attribute of the data in a table.
ViewA virtual table generated from a query.
IndexA data structure that improves the speed of data retrieval.
ConnectionAn active session between a client and a database server.
